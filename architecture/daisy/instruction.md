# Soundfile primitive support 

I'm implementing Soundfile primitive of Faust for faust2daisy tool. 
Regarding how it is done in architecture/gui/Soundfile.h, architecture/daisy folder, and how 
My approach is that the python parser of faust2daisy will look at metadata and if there is a soundfile. If it doesn't exist, it should return an error and exit. If file exists, it should be parsed and generate a C++ header that contains all data, parsed, in the same architecture as Soundfile.h. Except all data will be inlined in the file. The file should have a generic name, like daisy_soundfile.hpp. There should be no dynamic allocation. All samples should be placed in SDRAM. You can look at ~/tmp/daisy/soundfile.cpp to see how C++ code is generated by Faust for Soundfile. 
If there is a soundfile, python should print a USE_SOUNDFILE to true, so that faust2daisy script can know it, and add a #define USE_SOUNDFILE to the C++ code. The script itself  is in tools/faust2appls 

If needed, create a class heriting from Soundfile. Same for python WAV parser (we want to avoid dependency) that can be created as well. It should support WAV PCM : int 16, 24 or 32 bit and float 32.
